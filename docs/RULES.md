# MobMind 玩法与开发规则

## 开发硬规则

- 不使用 Mixin，除非 NeoForge 事件/API 无法实现目标。
- 第一阶段不添加自定义实体、模型、贴图或新怪物。
- 视觉表现优先使用原版资源：装备、发光、自定义名称、粒子、状态效果、原版方块。
- 不给原版实体添加 `SynchedEntityData`。
- 单个怪物数据使用 NeoForge Data Attachments。
- 世界级或小队级数据使用 `SavedData` 或服务端 Manager。
- AI、首领选举、群体命令、庇护区建造和方块修改必须只在服务端执行。
- 所有破坏或放置方块逻辑必须经过 config 开关和安全检查。
- 每次功能修改后运行 `.\gradlew.bat build`。

## 当前玩法边界

- 当前只支持 `EntityType.ZOMBIE`，也就是普通原版僵尸。
- 暂不支持尸壳、溺尸、僵尸村民、骷髅、蜘蛛、苦力怕。
- 当前首领只有 1 级。
- 当前庇护区不是完整巢穴系统，只是临时避光和工作空间。
- 当前共享背包没有玩家 GUI，只作为小队内部资源池。

## awareness 规则

- 僵尸每 20 tick 增长一次 awareness。
- 存活时间越久，基础增长越稳定。
- 夜晚会提供额外增长。
- 附近 16 格内同类僵尸越多，额外增长越高。
- awareness 用于首领选举。

## 首领选举规则

- 每个 `ServerLevel` 每 200 tick 扫描一次。
- 扫描半径为 32 格。
- 候选僵尸 awareness 需要达到 100。
- 候选数量至少为 6。
- awareness 最高的僵尸成为首领。
- 其余 5 名成员被编入同一 `groupId`，并记录 `leaderUuid`。
- 成员按角色分工，不会无限收编附近僵尸。

## 首领规则

- 首领戴金头盔。
- 首领发光高亮。
- 首领显示自定义名称“觉醒僵尸首领”。
- 首领体型会变大。
- 首领获得少量生命值和攻击力提升。
- 首领发现玩家或被玩家攻击时，会命令小队攻击或保护首领。
- 首领生命值低于 30% 时，小队进入撤退。
- 首领死亡时，小队解散，共享背包内容掉落。

## 角色规则

- 护卫：靠近首领，首领被攻击时优先攻击攻击者。
- 巡逻：在首领或庇护区附近巡查，发现玩家后召集团队。
- 矿工：寻找庇护区清理目标，切换铁镐或铁铲，破坏允许方块。
- 建筑工：使用共享背包里的普通方块补庇护区外壳缺口。
- 撤退时所有角色停止本职行为，优先靠拢。

## 方块修改安全规则

矿工和建筑工不能绕过 `BlockChangeRules`。

禁止破坏或替换：

- 容器和所有方块实体。
- 床。
- 门。
- 红石相关方块。
- 铁轨。
- 刷怪笼。
- 命令方块。
- 水和岩浆。
- 其他被标记为敏感的功能方块。

矿工主要处理自然方块，例如石头、泥土、沙子、沙砾、深板岩等。建筑工主要放置普通建筑方块，例如圆石、泥土、石头、深板岩等。

## 配置规则

- `enableMobBlockBreaking` 控制怪物是否允许真实破坏方块。
- `enableMobBlockPlacing` 控制怪物是否允许真实放置方块。
- `maxBlocksChangedPerGroupPerMinute` 控制每个小队每分钟最多修改多少方块。

即使配置开启，代码也必须继续执行安全黑名单和节流限制。

## 测试规则

- 优先在临时测试世界测试。
- 不要直接在重要建筑附近开启方块修改测试。
- 首领、小队、角色和共享背包可以用 debug 命令检查。
- 每次代码修改后运行构建。
